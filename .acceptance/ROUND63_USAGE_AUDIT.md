# Round 63 — USG-03 cost-per-model audit findings

`UsageStatisticsAggregator` already groups by normalized model and sums non-nil `costUSD`, preserving `nil` for providers where cost is not applicable. `ProjectDatabaseManager.insertMessage` and `updateMessageTokens` persist `UsageCapture.costUSD`; `usageDataPoints()` hydrates `messageCostUsd` into `UsageDataPoint.costUSD` for assistant messages. The remaining question is where provider response usage is converted into `UsageCapture`: if all call sites pass nil or omit pricing, the per-model UI can only display N/A even though the schema exists. Next trace all `UsageCapture` construction sites and provider pricing metadata before writing a targeted red regression.


`DirectChatClient.extractUsage` parses prompt/completion tokens and `cost_usd`/`cost`, then creates `UsageCapture`; its ChatPanel branch assigns `directResult.usage` to the assistant message. ACP creates a nil-cost `UsageCapture` because ACP usage has no price. MiCoder Auto Free’s streaming branch never creates or assigns UsageCapture. The web branch delegates to `runWebChatTurn`; the Serve branch is SSE-driven and the inspected post-send branch does not yet show a UsageCapture assignment. Therefore USG-03 is not just a UI aggregation gap: actual per-model costs are available only when a direct gateway supplies them, while web/Auto Free/Serve usage either has no price metadata or is not persisted. A fix must preserve N/A where provider pricing is unknowable and avoid fabricated costs.


`DatabaseManager.usageDataPoints()` now hydrates `messageCostUsd` correctly, so the registry note’s older “hardcodes nil” wording is stale. The confirmed current defect is in `AppState+Database.loadUsageDataPoints()`: it returns only `DatabaseManager.shared.usageDataPoints()` from the legacy/global database. Round 57 made per-project databases canonical, and `ProjectDatabaseManager.usageDataPoints()` already exposes model/provider/cost rows, but UsageSettingsView never aggregates those project databases. This explains missing per-model cost for normal project sessions. The minimal safe fix is to aggregate legacy plus each project DB’s usage points with a deduplication policy that avoids double-counting migrated/duplicate session IDs if both stores contain the same message.
